Goals that match a recipe, or they don't run.

Errands runs narrow goals as fixed, verified recipe sequences. A goal matches a recipe or it does not — and when it does not, Errands says so. No generative planning. Every step is verified against the page, and a plan-aware gate (Sentinel) classifies each action in the context of what comes next.

The three gates

1

Preflight

Before step one: the page must match the recipe's preconditions. Drift outranks a plain miss — an expired session has no cart, no plan, no account; reporting "expected cart, found none" sends someone hunting for the wrong thing.

2

Sentinel (plan-aware)

Every step: the action is classified with the full plan context — errand name, goal, this step's intent, and what comes next. A click on "Continue" is low in isolation and destructive when the plan says payment is next. The deterministic layer decides; the classifier (AUC 0.5378 = coin flip) stays ADVISORY.

3

Verify

After every step: the step did what it claimed. Any expect word present = success. Any reject word present = definitive failure. unless_present skips steps already done. A step that cannot verify stops the run — there is no "continue anyway".

Refusals are named

ReasonMeaning
no_matchno recipe fits the goal confidently
ambiguoustwo recipes fit equally well — a question, not a coin flip
precondition_failedthe page is not what the recipe expects
driftthe page changed under the recipe
unsafea step needs a human and did not get one
verification_faileda step ran and could not prove itself

Recipes are data (JSON)

A recipe checked against a real site gets reviewed and diffed like a data file, not skimmed like code.

{
  "name": "cancel_subscription",
  "triggers": ["cancel my subscription", "end my premium plan"],
  "preconditions": [{ "id": "on_account_page", "expect": ["account", "settings"] }],
  "steps": [
    { "id": "open_plan", "tool": "browse_click",
      "args": { "selector": "text=Manage plan" },
      "intent": "open the subscription settings",
      "expect": ["subscription", "renews"] }
  ]
}
  • expect — any one word present = success (acceptable wordings, not conjunction)
  • reject — word presence = definitive failure (checked first)
  • unless_present — skip step if all these words are already on the page
  • gated: false — opt a read-only step out of the Sentinel gate

Unknown keys are an error, not a warning. A misspelled expectd would otherwise produce a step that verifies nothing and reports success.
